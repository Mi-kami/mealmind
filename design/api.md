## Overview

MealMind has **one serverless endpoint** (LLM narration) and relies on the **Supabase client SDK** for all data operations. There is no custom REST API for CRUD — Supabase handles that via its auto-generated PostgREST layer with RLS enforcing access control.

Base URL (production): `https://mealmind.netlify.app`  
Base URL (local dev): `http://localhost:8888`

---

## Netlify Serverless Functions

### `POST /api/narrate`

**Purpose:** Accepts pre-computed score data for a meal suggestion and returns a plain-language explanation generated by the LLM. This is the only endpoint where the LLM is involved. The function holds the API keys server-side.

**Request:**

```json
POST /api/narrate
Content-Type: application/json

{
  "dish_name": "Jollof Rice",
  "meal_type": "dinner",
  "persona": "professional",
  "scores": {
    "variety": 0.82,
    "nutrition": 0.74,
    "effort": 0.91,
    "ingredient_match": 0.88
  },
  "weights": {
    "variety": 0.20,
    "nutrition": 0.25,
    "effort": 0.35,
    "ingredient_match": 0.20
  },
  "final_score": 0.86,
  "missing_ingredients": ["bay leaves"]
}
```

**Response (success):**

```json
HTTP 200
{
  "narration": "Jollof Rice scores well tonight because it fits your available ingredients almost perfectly and takes a reasonable amount of effort for a weeknight dinner. The nutritional balance is solid too — a good pick for a professional evening meal.",
  "model_used": "groq",
  "latency_ms": 312
}
```

**Response (fallback used):**

```json
HTTP 200
{
  "narration": "...",
  "model_used": "gemini",
  "latency_ms": 891
}
```

**Response (both models failed):**

```json
HTTP 200
{
  "narration": "This meal was suggested because it scored well on effort fit, ingredient availability, and nutritional balance based on your current preferences.",
  "model_used": "template",
  "latency_ms": 0
}
```

> Note: Returns HTTP 200 even on fallback — the UI never crashes. Only returns HTTP 500 on a malformed request.

**Validation:**
- `dish_name` required, string, max 100 chars
- `meal_type` required, one of: `breakfast`, `lunch`, `dinner`, `any`
- `persona` required, one of: `student`, `professional`, `family`, `other`
- `scores` required, all four sub-scores present, values between 0.0 and 1.0
- `weights` required, all four weights present, must sum to approximately 1.0 (±0.01 tolerance)
- `final_score` required, float between 0.0 and 1.0
- `missing_ingredients` optional, array of strings

**Authentication:** None — narration is stateless and contains no user-identifiable data.

**Error cases:**

| Status | Cause | Response |
|---|---|---|
| 400 | Missing required field | `{ "error": "Missing field: scores" }` |
| 400 | Score out of range | `{ "error": "Score values must be between 0 and 1" }` |
| 400 | Weights don't sum to ~1.0 | `{ "error": "Weights must sum to 1.0" }` |
| 500 | Unhandled server error | `{ "error": "Internal server error" }` |

**Rate limiting:** Netlify's default applies (125k calls/month free tier). No additional rate limiting in v1.0.

## Supabase Client SDK Operations

These are not custom REST endpoints — they use the Supabase JS client directly in the frontend. Listed here for completeness and to validate against the PRD.

### Auth Operations

| Operation | SDK Call | When |
|---|---|---|
| Sign up (email) | `supabase.auth.signUp({ email, password })` | Registration form submit |
| Sign in (email) | `supabase.auth.signInWithPassword({ email, password })` | Login form submit |
| Sign in (Google) | `supabase.auth.signInWithOAuth({ provider: 'google' })` | Google button click |
| Sign out | `supabase.auth.signOut()` | User clicks sign out |
| Get session | `supabase.auth.getSession()` | App load, route guard |
| Auth state change | `supabase.auth.onAuthStateChange()` | Global listener in app root |

---

### User Profile Operations

| Operation | Table | When |
|---|---|---|
| Create profile after signup | INSERT `users` | Post-onboarding submit |
| Load profile on login | SELECT `users` WHERE `id = auth.uid()` | App load |
| Update dietary filters | UPDATE `users` SET `dietary_filters` | Filter settings change |
| Update cuisine preference | UPDATE `users` SET `cuisine_preference` | Preference settings change |
| Mark onboarded | UPDATE `users` SET `onboarded = true` | Onboarding complete |

---

### Scoring Weights Operations

| Operation | Table | When |
|---|---|---|
| Create default weights | INSERT `scoring_weights` | Post-onboarding (persona sets defaults) |
| Load weights | SELECT `scoring_weights` WHERE `user_id = auth.uid()` | App load, after login |
| Update weights after feedback | UPDATE `scoring_weights` SET weights + `feedback_count` | Every accept/skip/reject event |

---

### Pantry Operations

| Operation | Table | When |
|---|---|---|
| Load pantry | SELECT `pantry` WHERE `user_id = auth.uid()` | App load, pantry screen open |
| Add ingredient | INSERT `pantry` | User adds ingredient |
| Remove ingredient | DELETE `pantry` WHERE `id = ?` AND `user_id = auth.uid()` | User removes ingredient |
| Clear pantry | DELETE `pantry` WHERE `user_id = auth.uid()` | User clears all |

---

### Meal History Operations

| Operation | Table | When |
|---|---|---|
| Load recent history | SELECT `meal_history` WHERE `user_id = auth.uid()` ORDER BY `suggested_at DESC` LIMIT 30 | Before scoring run |
| Record accepted meal | INSERT `meal_history` | User taps Accept on a suggestion |

---

### Feedback Operations

| Operation | Table | When |
|---|---|---|
| Log feedback event | INSERT `feedback_events` | Every accept/skip/reject/reroll action |

> `feedback_events` is insert-only. No updates or deletes in v1.0.

## Client-Side Engine Interface (Not an API, but documented here for Day 4 reference)

These are the internal function signatures the scoring engine exposes. Included here so Day 4 can implement against a clear contract without redesigning.

```typescript
// filters.js
filterDishes(
  dishes: Dish[],
  activeFilters: string[]
): Dish[]

// variety.js
applyVarietyPenalty(
  dishes: Dish[],
  recentHistory: { dish_id: string; suggested_at: string }[],
  penaltyWindowDays: number  // default: 5
): Dish[]  // returns dishes with variety_score attached

// matching.js
computeIngredientMatch(
  dish: Dish,
  availableIngredients: string[]
): { score: number; missing: string[] }

// scoring.js
computeSubScores(
  dish: Dish,
  availableIngredients: string[],
  recentHistory: object[],
  userProfile: { persona: string; cuisine_preference: string }
): { variety: number; nutrition: number; effort: number; ingredient_match: number }

scoreDish(
  dish: Dish,
  subScores: SubScores,
  weights: WeightVector
): number  // final weighted score 0.0–1.0

rankDishes(
  dishes: Dish[],
  availableIngredients: string[],
  recentHistory: object[],
  weights: WeightVector,
  userProfile: object,
  activeFilters: string[]
): RankedDish[]  // sorted descending by final score

// feedback.js
applyFeedback(
  currentWeights: WeightVector,
  subScores: SubScores,
  action: 'accepted' | 'skipped' | 'rejected',
  learningRate: number  // default: 0.05
): WeightVector  // new weight vector, clamped to [0.05, 0.60] per dimension

// personas.js
getPersonaDefaults(
  persona: 'student' | 'professional' | 'family' | 'other'
): WeightVector
```
